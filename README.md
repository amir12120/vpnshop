# VPN Shop — فروشگاه فروش کانفیگ VPN

فروشگاه سبک و متن‌باز برای فروش کانفیگ‌های V2Ray/VLESS با پرداخت **کارت به کارت** و تحویل خودکار از طریق **API پنل سنایی (3x-ui / X-UI)**.

بدون فریم‌ورک سنگین: **Node.js خالص + SQLite داخلی Node** — فقط یک پکیج وابستگی (`qrcode`). روی یک سرور معمولی Ubuntu (حتی کوچک) نصب می‌شود و با معماری «سرور ایران + تانل به پنل روی سرور خارج» کاملاً سازگار است.

## امکانات

**برای مشتری**
- عضویت و ورود، مشاهده پلن‌ها از صفحه تمیز «پلن‌ها» (`/plans`) بدون سربرگ اضافه
- انتخاب بسته بر اساس **حجم / زمان / هر دو** و انتخاب **نام اکانت کانفیگ** دلخواه
- پرداخت **کارت به کارت**: آپلود تصویر فیش واریزی + توضیح اختیاری
- تحویل خودکار پس از تأیید مدیر: **QR Code + لینک اشتراک + لینک هر کانفیگ**
- **لینک اشتراک با مسیر تصادفی** (نام اکانت مشتری در لینک اشتراک لو نمی‌رود)
- دکمه **کپی** کنار هر لینک و دکمه **«کپی همه لینک‌ها»**
- اتصال به چند اینباند در یک سفارش → یک لینک کانفیگ برای هر اینباند
- **پنل کاربری با سایدبار**: داشبورد / سفارش‌ها و کانفیگ‌ها / خرید بسته / پروفایل (تغییر رمز) و خروج
- **داشبورد مصرف**: تعداد کانفیگ‌ها، کل حجم خریداری‌شده، مصرف کل و حجم باقی‌مانده + نوار پیشرفت هر کانفیگ (فعال/منقضی/نزدیک اتمام)
- **نمودار مصرف ساعتی، روزانه و ماهانه** (با سوئیچ لحظه‌ای) با اعداد و ماه‌های شمسی
- **متر مصرف خودکار**: فروشگاه هر ۲ دقیقه از پنل نمونه برمی‌دارد (قابل تنظیم با `meter_interval_s`؛ خاموشی با `METER_ENABLED=0`) و نمودارها از روی همین نمونه‌ها ساخته می‌شوند

**برای مدیر**
- اتصال **چند پنل سنایی** با **API Token** (بدون نیاز به نام کاربری/رمز پنل) + دکمه **تست اتصال**
- فیلد «آدرس عمومی لینک اشتراک (sub)» برای پنل‌هایی که پشت تانل هستند
- تحویل به اینباندهای دلخواه (با ویرگول) یا **انتخاب یکجا همه اینباندهای پنل** با یک کلید
- **نوتیفیکیشن سفارش جدید**: هر ۵ ثانیه بررسی می‌شود؛ سفارش تازه با پیام روی صفحه + بج شمارنده سفارش‌های در انتظار در هدر
- مشاهده تصویر فیش، تأیید / رد با دلیل، وضعیت هر سفارش و پیام خطای دقیق ساخت
- CLI مدیریت کامل: نصب، آپدیت، SSL، بکاپ/بازگردانی، تغییر پورت، ادمین، دکتر و …

**فنی**
- نصب تعاملی: هنگام نصب فقط **Username / Password / Domain / Port** پرسیده می‌شود و سایت دقیقاً روی `https://Domain:Port` بالا می‌آید
- pre-flight قبل از نصب: بررسی سرور، نصب پیش‌نیازها و تست دسترسی به گیت‌هاب با **fallback خودکار به دانلود tarball** (رفع خطای `RPC failed; HTTP 401`)
- امنیت: هش PBKDF2، سشن امضاشده HttpOnly، آپلود whitelist‌شده، فیش‌ها فقط برای صاحب سفارش و ادمین

## معماری

```
مشتری (ایران) ──► فروشگاه روی سرور ایران ──API از طریق تانل──► پنل سنایی (سرور خارج)
                       │
                       └─ SQLite + فیش‌های آپلودی (همه لوکال، در دیتابیس/پوشه محلی)
```

فروشگاه روی سرور ایران اجرا می‌شود (برای دسترسی کاربران ایرانی). به پنل سنایی که روی سرور خارج است، **فقط از طریق تونلِ موجود** با آدرس لوکال (مثل `http://127.0.0.1:PORT`) وصل می‌شود؛ پس پنل سنایی هیچ‌وقت روی اینترنت عمومی دیده نمی‌شود.

## نصب سریع

پیش‌نیاز: **Ubuntu 22.04+ با دسترسی روت**. با یک دستور، منوی CLI باز می‌شود (حتی روی سرور کاملاً خام):

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/amir12120/vpnshop/main/cli.sh)
```

گزینه‌های منو (بعد از نصب، همان منو با دستور `vpnshop` هم در دسترس است):

```
 1) Install            نصب فروشگاه روی این سرور (دامنه / پورت / ادمین)
 2) Update             دریافت آخرین نسخه از گیت‌هاب + ری‌استارت
 3) SSL manager        لِت‌س‌انکریپت، تمدید، وضعیت، حذف
 4) Status             وضعیت سرویس و آدرس‌های ورودی (https://Domain:Port)
 5) Doctor             چک سلامت: دیتابیس، پنل‌ها/تانل، آپلودها
 6) Ports              لیست پورت‌های در حال شنود (بررسی تداخل با تانل)
 7) Backup / Restore   بکاپ دیتابیس + فیش‌ها + کانفیگ‌ها
 8) Admin user         ساخت / ریست نام کاربری و رمز ادمین
 9) Uninstall          حذف کامل شامل دیتابیس (اول تأیید می‌گیرد؛ --keep-data داده‌ها را نگه می‌دارد)
 0) Exit
```

**گزینه ۱ (Install)** مخزن را در `/opt/vpnshop` نصب می‌کند، پیش‌نیازها (Node 24، nginx و…) را آماده می‌کند و فقط این چهار مورد را می‌پرسد (نصب‌کننده انگلیسی است):

```
Username :        ← نام کاربری ادمین
Password :        ← رمز ادمین (هنگام تایپ نمایش داده نمی‌شود)
Domain :          ← دامنه شما (خالی = سرو روی IP:PORT)
Port :            ← پورت عمومی سایت — آدرس نهایی: https://Domain:Port
SSL mode: 1/2     ← فقط وقتی دامنه داده باشید
```

در پایان نصب همه آدرس‌های ورودی با همان ترکیب و با نام کاربری/رمز واردشده نمایش داده می‌شود:

```
 Storefront (customers):  https://my-domain.ir:8443/
 Register:                https://my-domain.ir:8443/register
 Login:                   https://my-domain.ir:8443/login
 Admin panel:             https://my-domain.ir:8443/admin
 Admin username:          admin
 Admin password:          ********
```

### فاز pre-flight نصب‌کننده

قبل از هر تغییری روی سرور، این موارد بررسی می‌شوند:

1. **سرور** — دسترسی روت، نسخه اوبونتو، معماری CPU، فضای دیسک (حداقل ۲ گیگ)، رم و اتصال اینترنت خروجی
2. **پیش‌نیازها** — git، curl، rsync، tar، openssl و ca-certificates (فقط موارد غایب نصب می‌شوند)
3. **دسترسی به گیت‌هاب** — اول `git clone`؛ اگر با خطای `RPC failed; HTTP 401` مواجه شد (credential قدیمی / پروکسی / بلاک git)، خودکار به **دانلود مستقیم tarball** سوئیچ می‌کند و نصب متوقف نمی‌شود

دیباگ دستی:

```bash
bash /opt/vpnshop/scripts/preflight.sh
# خروجی: REPO_FETCH_MODE=git  یا  tarball
```

### نصب دستی

```bash
git clone https://github.com/amir12120/vpnshop.git /opt/vpnshop
cd /opt/vpnshop
npm install
node seed-admin.js admin YOUR_ADMIN_PASSWORD     # ساخت ادمین
PORT=3000 node server.js                         # اجرای خام (در پروداکشن: INSTALL.sh)
```

اگر `git clone` خطای `RPC failed; HTTP 401` داد:

```bash
curl -fsSL https://codeload.github.com/amir12120/vpnshop/tar.gz/refs/heads/main -o /tmp/vpnshop.tar.gz
mkdir -p /opt/vpnshop && tar -xzf /tmp/vpnshop.tar.gz -C /opt/vpnshop --strip-components=1
```

یا همه‌چیز خودکار (nginx، systemd، certbot، فایروال):

```bash
cd /opt/vpnshop && bash INSTALL.sh
```

## مدیریت با CLI

دستور **`vpnshop`** بعد از نصب در `/usr/local/bin/vpnshop` قرار می‌گیرد و از هر جای ترمینال در دسترس است:

```bash
vpnshop        # منوی تعاملی مدیریت
```

| دستور | کار |
|---|---|
| `vpnshop status` | وضعیت سرویس، آدرس‌ها، مصرف دیسک |
| `vpnshop start \| stop \| restart` | کنترل سرویس |
| `vpnshop logs [n]` | آخرین n خط لاگ (پیش‌فرض ۵۰) |
| `vpnshop update` | دریافت آخرین نسخه از گیت‌هاب + ری‌استارت |
| `vpnshop port <port>` | تغییر پورت فروشگاه (سرویس + nginx) |
| `vpnshop admin <user> <pass>` | ساخت / ریست کاربر ادمین |
| `vpnshop backup [file]` | بکاپ دیتابیس + فیش‌ها + کانفیگ‌ها |
| `vpnshop restore <file>` | بازگردانی بکاپ |
| `vpnshop ssl` | منوی تعاملی SSL |
| `vpnshop ssl letsencrypt <domain>` | فعال‌سازی HTTPS → `https://Domain:Port` |
| `vpnshop ssl renew` | تمدید اجباری گواهی‌ها |
| `vpnshop ssl remove` | بازگشت به HTTP ساده |
| `vpnshop doctor` | چک سلامت: دیتابیس، دسترسی پنل‌ها/تانل، آپلودها |
| `vpnshop ports` | همه پورت‌های در حال شنود (بررسی تداخل با تانل) |
| `vpnshop install` | اجرای مجدد نصب‌کننده (داده‌های قبلی حفظ می‌شود) |
| `vpnshop uninstall` | **حذف کامل**: سرویس، nginx، سرتیفیکت و دیتابیس (با تأیید شما) |
| `vpnshop uninstall --keep-data` | فقط توقف سرویس — همه داده‌ها و فایل‌ها حفظ می‌شود |
| `vpnshop help` | راهنمای کامل |

**مدیر SSL:** قبل از صدور گواهی، پورت 80 بررسی می‌شود: اگر آزاد بود گواهی standalone صادر می‌شود؛ اگر nginx روی آن بود nginx موقتاً stop و بعد start می‌شود؛ اگر پروسه دیگری (مثل تانل) روی 80 بود خطا می‌دهد و کاری انجام نمی‌دهد. هوک‌های تمدید خودکار هم نصب می‌شوند.

> اگر فروشگاه را قبل از اضافه‌شدن CLI نصب کرده بودید، یک بار:
> ```bash
> cd /opt/vpnshop && git pull
> install -m 0755 /opt/vpnshop/vpnshop-cli.sh /usr/local/bin/vpnshop
> vpnshop --version && vpnshop help
> ```

## راه‌اندازی پس از نصب

### آدرس‌ها (فرمت `https://Domain:Port`)

| بخش | آدرس |
|---|---|
| فروشگاه (ورود مشتری) | `https://Domain:Port/` |
| عضویت مشتری | `https://Domain:Port/register` |
| پنل ادمین | `https://Domain:Port/admin` |

- پورتی که حین نصب می‌پرسید **پورت عمومی** است (روی nginx با SSL سرو می‌شود)؛ بک‌اند node روی پورت داخلی مجزا (پورت + ۱) اجرا می‌شود
- بدون SSL همان آدرس‌ها با `http://` کار می‌کنند؛ بدون دامنه، سایت روی `http://IP:PORT` بالا می‌آید
- کاربر ناشناس که `/admin` را باز کند به `/login` هدایت می‌شود

### پیکربندی ادمین

1. وارد `https://Domain:Port/admin` شوید (همان نام کاربری/رمز نصب)
2. **تنظیمات فروشگاه** → شماره کارت واریز و نام صاحب کارت
3. **پنل‌های سنایی** → پنل را اضافه کنید:
   - **آدرس پنل**: اگر پنل فقط از طریق تانل در دسترس است، آدرس لوکال تانل مثل `http://127.0.0.1:PORT` — هرگز آدرس عمومی سرور خارج را نگذارید
   - **API Token**: از پنل سنایی (تنظیمات → API Tokens) توکن بسازید و اینجا بگذارید؛ برای پنل v3 همین کافی است (نام کاربری/رمز مدیر پنل فقط برای پنل‌های قدیمی v2 لازم است)
   - **آدرس عمومی لینک اشتراک (sub)**: آدرسی که مشتری به آن وصل می‌شود (مثل `https://sub-domain:2096/amirr/`) — اگر پنل پشت تانل است حتماً این را پر کنید وگرنه لینک اشتراک برای مشتری خراب است
   - دکمه **«تست اتصال»** → باید لیست inboundهای پنل را نشان دهد
4. **پلن‌ها** → بسته‌ها را تعریف کنید (نام، حجم GB، مدت روز، قیمت تومان، تعداد دستگاه، Inbound پیش‌فرض اختیاری، فعال/غیرفعال)
5. تمام — مشتری‌ها از صفحه اصلی یا صفحه «پلن‌ها» خرید می‌کنند

## جریان سفارش و تحویل

```
مشتری: انتخاب پلن → مشاهده شماره کارت → (اختیاری) نام اکانت دلخواه
      → آپلود تصویر فیش واریزی → سفارش «در انتظار تأیید مدیر»
ادمین: در /admin نوتیفیکیشن ۵ ثانیه‌ای سفارش جدید + بج در انتظار
      → مشاهده فیش → انتخاب پنل سنایی + اینباند(ها)
      → «تأیید و تحویل خودکار» (یا دکمه «همه Inboundهای این پنل»)
      → ساخت کلاینت روی پنل با حجم/انقضای پلن و نام اکانت دلخواه مشتری
مشتری: در «سفارش‌های من»: QR + لینک اشتراک + لینک هر کانفیگ + دکمه‌های کپی
```

نکات مهم:

- **نام اکانت**: مشتری فقط نام اکانت (ایمیل) را انتخاب می‌کند؛ همان روی پنل ساخته می‌شود. اگر گرفته باشد، خودکار پسوند می‌گیرد (`ali` → `ali_2`)
- **مسیر اشتراک تصادفی**: لینک اشتراک به شکل `sub-address/<path-تصادفی>` ساخته می‌شود و هرگز شامل نام اکانت نیست
- **چند اینباند**: در فرم تأیید می‌توانید چند اینباند را با ویرگول بنویسید (`1,2,3`) یا با دکمه **«✨ همه Inboundهای این پنل را انتخاب کن»** همه اینباندهای پنل را یکجا بدهید؛ تحویل شامل یک لینک کانفیگ برای هر اینباند + QR + لینک اشتراک است
- **خطاها پنهان نمی‌مانند**: اگر اتصال به پنل یا ساخت کلاینت خطا بدهد، پیام قرمز دقیق روی صفحه ادمین می‌آید و سفارش برای تلاش دوباره برمی‌گردد
- **کپی لینک‌ها**: کنار لینک اشتراک و هر لینک کانفیگ دکمه کپی هست و یک دکمه **«کپی همه لینک‌ها»** همه را یکجا کپی می‌کند

> ⚠️ **لینک اشتراک:** اگر پنل را با آدرس تانل ثبت کرده باشید، لینک ساخته‌شده از آن آدرس روی گوشی مشتری کار نمی‌کند — فیلد **آدرس عمومی لینک اشتراک** را با آدرسی که کلاینت کاربر به آن وصل می‌شود (دامنه عمومی پنل یا آدرس عمومی سمت ایران تانل) پر کنید.

## سازگاری با تانل

فروشگاه برای معماری «سرور ایران + تانل به پنل روی سرور خارج» طراحی شده و با تانل ریورس و مستقیم تداخل ندارد:

- فقط **پورت خودش** را گوش می‌دهد و listener دیگری نمی‌سازد
- اتصال به پنل سنایی همیشه **خروجی** است (فروشگاه به آدرس تانل درخواست می‌زند، منتظر اتصال ورودی نمی‌ماند)
- فایروال روی loopback اثری ندارد؛ فورواردهای لوکال تانل امن‌اند
- nginx فقط روی 80 (و بعد از SSL روی 443) بالا می‌آید

**سه نکته برای جلوگیری از تداخل پورت:**

1. پورت فروشگاه نباید با پورت‌های تانل یکی باشد — نصب‌کننده پورت اشغال را تشخیص می‌دهد؛ برای مشاهده: `vpnshop ports`
2. اگر تانل شما پورت 80 یا 443 سرور ایران را اشغال کرده، موقع نصب دامنه را خالی بگذارید یا اول پورت 80 را آزاد کنید
3. آدرس پنل را همیشه به‌صورت آدرس لوکال تانل ثبت کنید (`http://127.0.0.1:PORT`) — سلامت تانل را با «تست اتصال» یا `vpnshop doctor` چک کنید

## پشتیبان‌گیری و حذف

```bash
vpnshop backup                    # بکاپ کامل (دیتابیس + فیش‌ها + کانفیگ‌ها)
vpnshop restore backup.tar.gz     # بازگردانی
tar czf backup.tar.gz /opt/vpnshop/data /opt/vpnshop/public/uploads   # بکاپ دستی
```

- `vpnshop uninstall` → **حذف کامل**: سرویس، کانفیگ nginx، سرتیفیکت‌ها و `/opt/vpnshop` **شامل دیتابیس** (اول تأیید می‌گیرد). نصب مجدد از صفر و تمیز شروع می‌شود
- `vpnshop uninstall --keep-data` → فقط توقف سرویس؛ دیتابیس، فیش‌ها و فایل‌ها سر جایش می‌مانند

```bash
npm install
node seed-admin.js admin adminpass123

## امنیت

- رمزها: **PBKDF2-SHA512** (هرگز متن ساده ذخیره نمی‌شود)
- سشن: کوکی امضاشده HMAC-SHA256، **HttpOnly**، انقضای ۷ روزه
- آپلود: فقط `jpg/png/webp`، حداکثر ۸ مگابایت، نام تصادفی
- فیش‌ها: فقط صاحب سفارش و ادمین (برای بقیه 403)
- دیتابیس و فیش‌ها (`data/`، `public/uploads/`) در `.gitignore` هستند و هرگز وارد مخزن نمی‌شوند
- دسترسی SSH به سرور را به کلید محدود کنید — توکن API پنل سنایی در دیتابیس محلی ذخیره می‌شود
