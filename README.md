# 🛒 VPN Shop — فروشگاه فروش کانفیگ VPN (متصل به پنل سنایی / X-UI)

فروشگاه سبک و متن‌باز برای فروش کانفیگ‌های V2Ray/VLESS با پرداخت **کارت به کارت** و تحویل خودکار از طریق **API پنل سنایی (3x-ui / X-UI)**.

بدون فریم‌ورک سنگین: Node.js خالص + SQLite داخلی Node — فقط یک پکیج وابستگی (`qrcode`)، قابل نصب روی یک سرور معمولی Ubuntu.

## امکانات

- ✅ عضویت و ورود کاربران
- ✅ پلن‌های فروش بر اساس **حجم / زمان / هر دو**
- ✅ پرداخت **کارت به کارت**: مشتری **تصویر فیش واریزی** را در سایت بارگذاری می‌کند
- ✅ تأیید ادمین → ساخت خودکار کاربر روی پنل سنایی از طریق API
- ✅ تحویل خودکار: **QR Code + لینک اشتراک + لینک کانفیگ‌ها** (vless / vmess / trojan — شامل ws، tls، reality)
- ✅ اتصال **چندین پنل سنایی** + دکمه **تست اتصال** (مناسب معماری تونل ایران ↔ خارج)
- ✅ نصب تعاملی: دامنه، پورت، SSL و نام کاربری/رمز ادمین هنگام نصب پرسیده می‌شود
- ✅ امنیت: هش PBKDF2، سشن امضاشده HttpOnly، آپلود فیش با whitelist و سقف حجم، فیش‌ها فقط برای صاحب سفارش و ادمین

## معماری

```
مشتری ──► فروشگاه (سرور ایران) ──API از طریق تونل──► پنل سنایی (سرور خارج)
                │
                └─ دیتابیس SQLite + فیش‌های آپلودی (همه لوکال)
```

فروشگاه روی سرور ایران اجرا می‌شود (برای دسترسی کاربران ایرانی) و از طریق تونلِ موجود به API پنل سنایی روی سرور خارج وصل می‌شود. پنل سنایی نیازی به دسترسی عمومی ندارد.

## نصب سریع (Ubuntu 22.04 — دسترسی روت)

نصب‌کننده کاملاً به زبان انگلیسی است و به همین ترتیب می‌پرسد:

```
Username :        ← نام کاربری ادمین
Password :        ← رمز ادمین (حداقل ۸ کاراکتر، هنگام تایپ نمایش داده نمی‌شود)
Domain :          ← دامنه شما (خالی = سرو روی IP:PORT)
Port :            ← پورت عمومی سایت (پیش‌فرض 8443) — آدرس نهایی: https://Domain:Port
SSL mode: 1/2     ← فقط وقتی دامنه داده شده باشد
```

در پایان نصب، **همه لینک‌های ورودی با همان ترکیب** نمایش داده می‌شوند:

```
 Storefront (customers):  https://my-domain.ir:8443/
 Register:                 https://my-domain.ir:8443/register
 Login:                    https://my-domain.ir:8443/login
 Admin panel:              https://my-domain.ir:8443/admin
 Admin username:           admin
 Admin password:           ********
```

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/amir12120/vpnshop/main/INSTALL.sh)
```

اسکریپت مخزن را در `/opt/vpnshop` کلون می‌کند، پیش‌نیازها (Node 24، nginx) را نصب می‌کند و از شما **دامنه، پورت، نوع SSL و نام کاربری/رمز ادمین** را می‌پرسد. در پایان سایت روی دامنه/پورت انتخابی بالا می‌آید.

#### نصب با احتیاط کامل (پیش‌نیازها و بررسی سرور قبل از شروع)

نصب‌کننده حالا **قبل از هر تغییری** یک فاز pre-flight اجرا می‌کند:

1. **بررسی سرور** — دسترسی روت، نسخه اوبونتو، معماری CPU، فضای دیسک (حداقل ۲ گیگ)، رم، و اتصال خروجی اینترنت
2. **نصب پیش‌نیازها** — git، curl، rsync، tar، openssl و ca-certificates (فقط موارد غایب نصب می‌شوند)
3. **تست دسترسی به گیت‌هاب** — دو مسیر جداگانه امتحان می‌شود: پروتکل git (همان مسیری که خطای `RPC failed; HTTP 401` می‌دهد) و دانلود مستقیم tarball. هرکدام کار کرد، استفاده می‌شود — اگر git روی سرور شما بلاک یا خراب بود (مثلاً به‌خاطر credential قدیمی یا پروکسی)، نصب **به‌طور خودکار با دانلود tarball ادامه پیدا می‌کند** و متوقف نمی‌شود.

برای دیباگ دستی یک سرور:

```bash
bash /opt/vpnshop/scripts/preflight.sh
# خروجی: REPO_FETCH_MODE=git  یا  tarball
```

## نصب دستی

```bash
git clone https://github.com/amir12120/vpnshop.git /opt/vpnshop
cd /opt/vpnshop
npm install
node seed-admin.js admin YOUR_ADMIN_PASSWORD   # نام کاربری و رمز ادمین
PORT=3000 node server.js                        # اجرا (در پروداکشن: systemd / INSTALL.sh)
```

> اگر روی سرور ایران هنگام `git clone` خطای `RPC failed; HTTP 401` گرفتید، نصب‌کننده خودش به دانلود tarball سوئیچ می‌کند — یا دستی:
> ```bash
> curl -fsSL https://codeload.github.com/amir12120/vpnshop/tar.gz/refs/heads/main -o /tmp/vpnshop.tar.gz
> mkdir -p /opt/vpnshop && tar -xzf /tmp/vpnshop.tar.gz -C /opt/vpnshop --strip-components=1
> ```

یا همه‌چیز (nginx، systemd، certbot، فایروال) خودکار:

```bash
cd /opt/vpnshop && bash INSTALL.sh
```

## راه‌اندازی پس از نصب

### آدرس‌ها (فرمت جدید: `https://Domain:Port`)

از این نسخه، فروشگاه دقیقاً با ترکیبی که حین نصب داده می‌شود ساخته می‌شود:

| بخش | آدرس |
|---|---|
| فروشگاه (ورود مشتری) | `https://دامنه:پورت/` |
| عضویت مشتری | `https://دامنه:پورت/register` |
| پنل ادمین | `https://دامنه:پورت/admin` |

- پورتی که حین نصب می‌پرسد، **پورت عمومی** است (روی nginx با SSL سرو می‌شود)؛ بک‌اند node روی یک پورت داخلی مجزا (پورت + ۱) اجرا می‌شود
- اگر بدون SSL نصب کنید، همین آدرس‌ها با `http://` کار می‌کنند
- اگر دامنه ندهید، سایت روی `http://IP:PORT` سرو می‌شود
- کاربر ناشناس که `/admin` را باز کند خودکار به `/login` هدایت می‌شود

### ورود به پنل ادمین

آدرس پنل: `https://دامنه-شما:پورت/admin` (یا `http://IP:PORT/admin` بدون دامنه). همان نام کاربری/رمزی که حین نصب در پاسخ به `Username :` و `Password :` داده‌اید را وارد کنید.

1. وارد `/admin` شوید (کاربر ناشناس به `/login` هدایت می‌شود)
2. **تنظیمات فروشگاه** → شماره کارت واریز و نام صاحب کارت
3. **پنل‌های سنایی** → پنل را اضافه کنید:
   - از طریق تونل: آدرس `http://127.0.0.1:PORT` (پورتِ فورواردشده روی همین سرور) — هرگز آدرس عمومی سرور خارج را وارد نکنید
   - نام کاربری/رمز **مدیر پنل سنایی**
   - دکمه **«تست اتصال»** → باید لیست inboundها را نشان دهد
4. **پلن‌ها** → بسته‌ها را تعریف کنید (حجم/زمان/قیمت/تعداد دستگاه)
5. تمام — مشتری‌ها از صفحه اصلی خرید می‌کنند

## جریان سفارش

```
انتخاب پلن → مشاهده شماره کارت → آپلود فیش واریزی
   → سفارش «در انتظار تأیید مدیر»
ادمین: مشاهده فیش در /admin/orders → «تأیید و تحویل خودکار» (انتخاب پنل + inbound)
   → ساخت کلاینت روی پنل سنایی با حجم/انقضای پلن
   → مشتری در «سفارش‌های من»: QR + لینک اشتراک + لینک کانفیگ‌ها
```

⚠️ **نکته لینک اشتراک:** لینک اشتراک از Base URL پنل ساخته می‌شود. اگر پنل را با آدرس تونل ثبت کرده باشید، لینک روی گوشی مشتری کار نمی‌کند — آدرسی ثبت کنید که کلاینتِ کاربر بتواند به آن وصل شود (دامنه عمومی پنل یا IP عمومی سمت ایرانِ تونل).

## مدیریت با CLI (دستور `vpnshop`)

برای مدیریت فروشگاه، از دستور **`vpnshop`** استفاده کنید — همین یک کلمه، در ترمینالِ سرور:

```bash
vpnshop        # منوی تعاملی مدیریت را باز می‌کند
```

نصب‌کننده (`INSTALL.sh`) این دستور را به‌صورت خودکار در مسیر `/usr/local/bin/vpnshop` نصب می‌کند؛ بنابراین بعد از نصب، در هر جای ترمینال سرور با همان کلمه `vpnshop` در دسترس است (مثل هر دستور لینوکسی). لیست کامل دستورات:

```bash
vpnshop help                   # راهنمای کامل دستورات
```

```bash
vpnshop status                 # وضعیت سرویس، آدرس‌ها، مصرف دیسک
vpnshop restart                # ری‌استارت
vpnshop logs 100               # ۱۰۰ خط آخر لاگ
vpnshop update                 # دریافت آخرین نسخه از گیت‌هاب + ری‌استارت
vpnshop port 3001              # تغییر پورت (سرویس + nginx)
vpnshop admin admin رمز_جدید   # ساخت/ریست کاربر ادمین
vpnshop backup                 # بکاپ دیتابیس + فیش‌ها + کانفیگ‌ها
vpnshop restore backup.tar.gz  # بازگردانی بکاپ
vpnshop uninstall --purge      # حذف کامل (با --purge دیتا هم پاک می‌شود)
vpnshop help                   # لیست کامل دستورات
```

### مدیر SSL

```bash
vpnshop ssl                        # منوی تعاملی SSL
vpnshop ssl status                 # نمایش گواهی‌ها و تاریخ انقضا
vpnshop ssl letsencrypt shop.example.ir   # نصب HTTPS + فعال‌سازی تمدید خودکار
vpnshop ssl renew                  # تمدید اجباری گواهی‌ها
vpnshop ssl remove                 # بازگشت به HTTP ساده
```

**مدیریت پورت 80 هنگام صدور گواهی:** قبل از صدور، پورت 80 چک می‌شود:
- اگر آزاد باشد → گواهی standalone صادر می‌شود
- اگر nginx روی آن باشد → nginx موقتاً **stop** می‌شود، گواهی صادر و nginx دوباره **start** و بلاک 443 خودکار پیکربندی می‌شود (80 → ریدایرکت به 443)
- اگر پروسه دیگری (مثلاً تانل) روی 80 باشد → با نام پروسه خطا می‌دهد و کاری انجام نمی‌دهد

پس از نصب، هوک‌های pre/post تمدید خودکار هم نصب می‌شوند تا در هر تمدید، nginx موقتاً متوقف و دوباره استارت شود.

### اگر فروشگاه را قبل از اضافه شدن CLI نصب کرده‌اید

فقط یک بار مخزن را آپدیت و CLI را دستی نصب کنید:

```bash
vpnshop update 2>/dev/null || (cd /opt/vpnshop && git pull)
install -m 0755 /opt/vpnshop/vpnshop-cli.sh /usr/local/bin/vpnshop
vpnshop --version 2>/dev/null; vpnshop help    # تست
```

از این به بعد دستور `vpnshop` در دسترس است.

## سازگاری با تانل (ریورس و مستقیم)

این فروشگاه برای معماری «سرور ایران + تانل به پنل سنایی روی سرور خارج» طراحی شده و با تانل ریورس و مستقیم تداخلی ندارد، به این دلایل:

- فروشگاه فقط **پورت خودش** را گوش می‌دهد (پیش‌فرض 3000) و هیچ listener دیگری نمی‌سازد
- اتصال به پنل سنایی همیشه **خروجی** است — فروشگاه به آدرس تانل (مثلاً `http://127.0.0.1:2053`) درخواست می‌زند و منتظر اتصال ورودی نمی‌ماند
- فایروال (ufw) روی ترافیک loopback (`127.0.0.1`) اثری ندارد، پس فورواردهای لوکال تانل امن‌اند
- nginx فقط روی 80 (و بعد از SSL روی 443) بالا می‌آید

### سه نکته برای جلوگیری از تداخل پورت

1. **پورت فروشگاه نباید با پورت‌های تانل یکی باشد.** اگر تانل شما روی سرور ایران پورت‌هایی را فوروارد می‌کند، پورت دیگری برای فروشگاه انتخاب کنید. نصب‌کننده خودش پورت اشغال را تشخیص می‌دهد و خطا می‌دهد؛ برای دیدن همه پورت‌های اشغال: `vpnshop ports`
2. **اگر تانل شما پورت 80 یا 443 سرور ایران را اشغال می‌کند** (مثلاً برای دامنه/اشتراک پنل)، موقع نصب یا دامنه را خالی بگذارید (فروشگاه روی IP:PORT سرو می‌شود) یا اول پورت 80 را آزاد کنید — نصب‌کننده در این حالت هشدار می‌دهد
3. **آدرس پنل را همیشه به‌صورت آدرس لوکال تانل ثبت کنید** (`http://127.0.0.1:PORT`) تا پنل از اینترنت عمومی دیده نشود — «پنل‌های سنایی → تست اتصال» یا `vpnshop doctor` سلامت تونل را چک می‌کند

### تشخیص سلامت (doctor)

```bash
vpnshop doctor     # دیتابیس، دسترسی‌پذیری همه پنل‌های سنایی از مسیر تونل،
                   # قابل نوشتن بودن پوشه فیش‌ها، فایل‌های یتیم
vpnshop ports      # لیست همه پورت‌های در حال گوش دادن (بررسی تداخل با تانل)
```

اگر doctor گفت پنلی unreachable است، یعنی تانل قطع شده یا پورت/آدرس تانل عوض شده — تونل را برقرار کنید و دوباره امتحان کنید.

## امنیت

- رمزها: PBKDF2-SHA512 (بدون ذخیره متن ساده)
- سشن: کوکی امضاشده HMAC-SHA256، HttpOnly، انقضای ۷ روزه
- آپلود: فقط jpg/png/webp، حداکثر ۸ مگابایت، نام تصادفی
- فیش‌ها: فقط صاحب سفارش و ادمین (۴۰۳ برای بقیه)
- **دسترسی SSH به سرور را به کلید محدود کنید** — رمز پنل‌های سنایی در دیتابیس ذخیره می‌شود
- دیتابیس و فیش‌ها (`data/`، `public/uploads/`) در `.gitignore` هستند و هرگز به مخزن وارد نمی‌شوند
